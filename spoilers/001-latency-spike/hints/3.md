The event loop is blocked for one to three seconds at a time, every few seconds. Something runs a long stretch of synchronous JavaScript, and every other request waits behind it.

Find the request that is slow *by itself*: in Jaeger, look at the slowest operation of `shopflow-api` and its trace. You'll see a short database span, then a long stretch with no child spans at all.

Then find out what fills that stretch: **Grafana → Drilldown → Profiles**, service `shopflow-api`, profile type `wall/cpu`, last 15 minutes. The flame graph names the functions burning the CPU, with file and line. (Or stop the traffic, attach Chrome DevTools to `127.0.0.1:9229`, and record a CPU profile while you call that endpoint yourself.)
