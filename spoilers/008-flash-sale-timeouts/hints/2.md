The slow span is the `SELECT id, stock FROM products … FOR UPDATE` at the start of the order's transaction. It's waiting for row locks (`wait_event_type = Lock`), in a line of sessions where each one is blocked by the one before.

At the head of each line is a session that is `idle in transaction`: PostgreSQL is waiting for the API to send its next query, and the transaction keeps its locks meanwhile. Which rows are the lines waiting for? `pg_locks` gives each waiter's row as a page and a tuple number, which you can turn into a product:

```sql
SELECT l.pid, (SELECT id FROM products WHERE ctid = format('(%s,%s)', l.page, l.tuple)::tid) AS product_id
  FROM pg_locks l
 WHERE l.locktype = 'tuple' AND l.relation = 'products'::regclass;
```
