The coupon checkout opens its transaction by hand (`pool.connect()`, `BEGIN`) and only reaches `COMMIT` and `client.release()` on the happy path. When a coupon isn't valid, it throws in between: the connection never returns to the pool, and its transaction keeps the coupon row locked. Every other order that tries the same coupon waits on that lock, holding a connection too. Ten of those and the pool is empty. Without a connection timeout, everything else waits forever.

Make every path end the transaction and release the connection. This codebase already has a helper that does exactly that. Then ask whether the pool should really wait forever.
