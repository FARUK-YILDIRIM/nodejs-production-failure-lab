This is the N+1 query pattern: one query for the orders, then one per order for its items, then one per item for its product. Each query is fast inside PostgreSQL (well under 0.1 ms), but each costs a ~6 ms round trip to a database in another availability zone, paid sequentially. A customer with 23 orders and 53 items pays it 77 times.

Fetch the same data with a fixed number of queries, whatever the size of the page: all the items of all the orders at once (`WHERE order_id = ANY($1)`), with the product and category columns joined in.
