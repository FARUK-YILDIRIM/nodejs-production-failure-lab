The API never reads `Idempotency-Key`, and gives PayFlow a new random key for every request, so PayFlow can't recognize a retry either. Only CrediBank cards take longer than the app waits, so only their checkouts get retried, up to four times: four orders, four holds, and a "checkout failed" in the app.

Make every attempt of a checkout lead to the same order: store the key with the order, under a unique constraint (two attempts can race each other), return the existing order when an attempt finds one, and give PayFlow a key derived from the app's. When an attempt arrives while the first one is still waiting for the card network, PayFlow answers 409: tell the app to come back in a moment (`409` with a `Retry-After` header).
